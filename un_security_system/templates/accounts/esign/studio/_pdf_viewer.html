{% comment %} accounts/templates/accounts/esign/studio/_pdf_viewer.html — StudioPDF StudioPDF.renderInto(container, source, {maxPages, width, onPage}) StudioPDF.load(source) -> pdf.js document (organiser, editor, image export) StudioPDF.renderPage(pdf, pageNumber, {width|scale}) source is a URL string, or {url, data, bytes}: data base64 PDF embedded in the page (see inline_pdf in studio_common_esign) bytes a Uint8Array already in memory (e.g. a preview) url where the PDF can also be fetched / opened Why it is built this way — each layer covers a failure seen in the field: 1. Embedded bytes first, so no separate request is needed (CSP connect-src, proxies, extensions, interrupted downloads). URL fetches are checked: status, a sign-in page instead of a PDF, or not a PDF at all. 2. pdf.js is served from this site's static files, not a CDN. If its worker can't start, pdf.js runs it on the page instead. 3. If pdf.js still can't draw it, the browser's own PDF viewer shows the document, and the reason is written under it — never a dead end. {% endcomment %}
