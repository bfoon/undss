{% comment %} Shared PDF.js bootstrap + diagnostic loader. Include ONCE per page, before any script that renders a document: {% include "accounts/esign/_pdf_loader.html" %} Exposes window.EsignPdf: await EsignPdf.ready() – resolves when pdf.js is usable await EsignPdf.load(url) – returns a PDFDocumentProxy EsignPdf.showError(el, err, url) – renders an actionable error panel EsignPdf.load() accepts a document entry {url, data}. When `data` (base64) is present the PDF never travels as a separate HTTP request — it arrives inside the page HTML — which sidesteps CSP connect-src rules, proxies, extensions and aborted streaming responses entirely. Why not just call pdfjsLib.getDocument(url)? • getDocument(url) issues HTTP Range requests, which nginx/Django can answer in ways pdf.js rejects. We fetch the bytes ourselves and hand over an ArrayBuffer, which removes that whole class of failure. • A plain fetch surfaces the real problem — 403, 404, a login redirect, or an HTML error page — instead of collapsing everything into "could not render". • If the worker script is blocked (CSP, offline, proxy) we retry with the worker disabled rather than failing outright. Self-hosting: set ESIGN_PDFJS_BASE in settings.py to a static prefix, e.g. ESIGN_PDFJS_BASE = "/static/vendor/pdfjs" and place pdf.min.js + pdf.worker.min.js there. {% endcomment %}
